# EVA

**Evolving Virtual Assistant** — автоматически самоорганизующаяся распределённая система для выполнения задач искусственного интеллекта на гетерогенном домашнем кластере.

EVA — это не просто локальный ИИ-ассистент и не обычный вычислительный кластер. Её задача — самостоятельно управлять распределёнными вычислительными ресурсами: обнаруживать доступные устройства, определять их возможности, распределять задачи, следить за состоянием оборудования и адаптировать конфигурацию кластера без жёсткой привязки к конкретным моделям железа.

## Возможности (целевые)

1. Обнаружение новых устройств в сети.
2. Определение доступных вычислительных ресурсов.
3. Регистрация и авторизация устройств.
4. Сбор и анализ нагрузки и состояния оборудования.
5. Выбор подходящего устройства для задачи.
6. Динамическое распределение вычислительной нагрузки.
7. Управление жизненным циклом моделей ИИ.
8. Восстановление после отказов.
9. Адаптация к изменению конфигурации кластера.
10. Единый интерфейс взаимодействия для пользователя.

## Архитектура

Система состоит из трёх самостоятельных программных проектов, объединённых в одном репозитории:

```
EVA/
├── EVA-Core/       # Центральный управляющий компонент
├── EVA-Agent/      # Представитель устройства
└── EVA-Contracts/  # Общий протокол взаимодействия (JSON Schema)
```

| Компонент | Роль |
|---|---|
| **EVA-Core** | Мозг и координатор: управление кластером, распределение задач, регистрация устройств, API и пользовательский интерфейс. |
| **EVA-Agent** | Средство связи между Core и конкретным устройством: сбор телеметрии, приём команд, выполнение задач. |
| **EVA-Contracts** | Общий «язык» системы: JSON Schema-контракты, события, команды, ошибки и форматы данных. |

Core и Agent обмениваются сообщениями строго по контрактам из `EVA-Contracts`. Каждый компонент развивается независимо; версии контрактов раздельные (SemVer).

## Текущее состояние

План разработки и статусы по фазам — в [`ROADMAP.md`](ROADMAP.md).

Детали по каждому модулю — в их README:

- **EVA-Contracts** — каркас протокола реализован: регистрация, capabilities, telemetry, WebSocket-сообщения (соединение/команды/события/heartbeat), общие схемы ошибок, реестр типов событий, политика версионирования, аутентификация. Каталог контрактов и статусов — в [`EVA-Contracts/CONTRACTS.md`](EVA-Contracts/CONTRACTS.md).
- **EVA-Core** — живой HTTP-сервер: эндпоинт регистрации узла, статус регистрации, информация об узле, приём capabilities и telemetry, in-memory хранилище, Swagger UI. Подробнее — [`EVA-Core/README.md`](EVA-Core/README.md).
- **EVA-Agent** — каркас: формирование запроса регистрации по контракту и отправка его на Core. Подробнее — [`EVA-Agent/README.md`](EVA-Agent/README.md).

## Быстрый старт

Подробности запуска — в README каждого компонента. Кратко:

- **Contracts**: валидация схем и примеров через `tools/validate_*.py`.
- **Core**: `uv run`/`python -m eva.main` внутри `.venv` проекта — поднимает HTTP-сервер на `127.0.0.1:8080` с Swagger UI на `/swagger`.
- **Agent**: `python -m eva_agent.main` внутри `.venv` проекта — отправляет запрос регистрации на Core.

## Стек

- Python 3.13+, aiohttp, aiohttp-swagger3, jsonschema.
- Контракты: JSON Schema (Draft 2020-12).
- Транспорт: HTTP (запросы), WebSocket (события).
